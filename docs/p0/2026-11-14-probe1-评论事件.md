# P0 探针 #1:文档评论消息接口验证记录

- 日期:2026-11-14
- 环境:lark-cli 1.0.97(app `cli_aa41c9f9c5789cbc`,user 身份)
- 结论:**事件链路当前不可用(unavailable)→ D5 启用评论 watcher 轮询降级**

## 实测过程

### 1. 订阅 API:可调用 ✔

```
$ lark-cli api POST /open-apis/drive/v1/user/subscription \
    --data '{"event_type":"drive.notice.comment_add_v1"}'
→ {"ok": true, "identity": "user", "data": {}}
```

订阅登记成功(无报错)。GET 复数路径 `/user/subscriptions` 404、DELETE `/user/subscription` 404——**只登记、不提供列出/退订端点**(经 CLI 透传);残留订阅无消费端,无功能影响。

### 2. 测试文档与首评:可发 ✔

```
$ lark-cli docs +create --title "P0探针-评论事件测试文档-可删除" \
    --doc-format markdown --content "..." --as user
→ doc H7wJd1jEtoK4owxF3MjcsBgbnCg
$ lark-cli drive +add-comment --doc H7wJ... --type docx \
    --content '[{"type":"text","text":"P0探针首评"}]' --as user
→ comment_id 7708027149189385233(comment_mode: full)
```

注意:`--content` 必须是 `[{type,text}]` JSON 数组,不是纯文本;裸 token 需 `--type docx`。

### 3. 二次回复:被文档评论设置拒绝 ✘(本探针文档上)

```
$ lark-cli drive +add-reply --token H7wJ... --type docx \
    --comment-id 7708027149189385233 --content '[{"type":"text","text":"..."}]' --as user
→ code 1069302 "The comment section does not allow replies"
```

`permission.public` 的 `comment_entity` 仅枚举 `anyone_can_view|anyone_can_edit`(谁能评论),**没有回复开关**;API 建文档的评论区默认禁回复。回复链路的实测移至 P0 #8(用真实任务文档,其评论区经用户手动开启或产品默认开启)。轮询侧的 reply 处理逻辑已有单测覆盖(`tests/test_comment_watcher.py`)。

### 4. 事件消费:CLI 不认识该 EventKey ✘(决定性)

```
$ lark-cli event consume drive.notice.comment_add_v1 --timeout 75s --as user
→ {"ok": false, "error": {"type": "validation", "subtype": "invalid_argument",
    "message": "unknown EventKey: drive.notice.comment_add_v1"}}
```

对照实验(证明是 key 缺位、非总线故障):对**已知** key `minutes.minute.generated_v1` 消费,报 `failed_precondition: requires event types not subscribed in console`(附控制台订阅二维码)——即已知 key 会走到「控制台订阅」前置检查,而 drive key 在键表查找阶段即被拒。`event list` 全量亦无任何 drive 条目。

## 结论与决策
